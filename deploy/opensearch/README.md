# IRON ID mail search (OpenSearch)

The mail engine keeps its full-text search index in OpenSearch instead of its own
database. This folder is a separate Railway service, named `opensearch`, in the same
project as `iron-id-mail`.

What you get over the engine's built-in search:

- Hyphenated words and codes match (`ZX-4471`, `e-mail`).
- Accents don't matter (`reunion` finds `Réunion`), nor do French elisions
  (`equipe` finds `l’équipe`) or Arabic spelling variants (`الاجتماع` finds `الإجتماع`,
  vowel marks and tatweel are ignored).
- The search index lives outside Postgres and can be rebuilt at any time.

## How it is put together

| Piece | Where | What it does |
|---|---|---|
| `Dockerfile` | this folder | Official OpenSearch 2.19.3 image, only the security plugin kept |
| `ironid-entrypoint.sh` | this folder | Creates private TLS certificates on first start, starts OpenSearch as a normal user, installs the search templates, then creates the engine's login |
| `templates/*.json` | this folder | The engine's exact index layout plus accent/elision/Arabic folding. Generated by `node make-template.js` from `engine-indexes-v0.16.23.json` |
| `security/*.yml` | this folder | One login, `stalwart`, which may only use the `st_*` mail indexes. No admin login exists; admin tasks use a certificate that never leaves the container |
| `webmail/services/searchBackend.js` | gateway | Points the engine at OpenSearch, starts the one-time re-index, reports `search` in `/healthz` |

Security:

- Not reachable from the internet. Never add a public domain to this service.
- Password login over TLS on Railway's private network. The certificate comes from a
  private certificate authority the container creates, so the engine skips certificate
  checking (`allowInvalidCerts`). The password still protects access.
- The engine reads `OPENSEARCH_PASSWORD` from its environment. The password is never
  stored in the engine's database.
- The index stores only search terms, not readable copies of messages (`_source` is off).

## Setup on Railway (one time)

1. Create the service and its volume. Deploy from the repo root:

   ```bash
   railway add --service opensearch
   railway volume add --mount-path /var/lib/ironid-search --service opensearch
   railway variable set OPENSEARCH_PASSWORD="$(openssl rand -hex 24)" --service opensearch
   railway up deploy/opensearch --path-as-root --service opensearch --detach
   ```

   Wait until its log shows `READY`. Give the service at least 1 GB of memory.

2. Connect the mail service:

   ```bash
   railway variable set 'OPENSEARCH_URL=https://${{opensearch.RAILWAY_PRIVATE_DOMAIN}}:9200' 'OPENSEARCH_PASSWORD=${{opensearch.OPENSEARCH_PASSWORD}}' --service iron-id-mail
   ```

3. Deploy `iron-id-mail` once with `STALWART_RECOVERY_ADMIN` set. `/healthz` then shows
   `"search":"restart-needed"`.

4. Remove `STALWART_RECOVERY_ADMIN` and deploy again. `/healthz` shows
   `"search":"reindexing"` for a few minutes, then `"search":"ok"`. New mail is
   searchable right away; older mail becomes searchable as the re-index runs.

## `/healthz` search values

| Value | Meaning |
|---|---|
| `builtin` | The engine uses its own search; `OPENSEARCH_URL` not set |
| `waiting-for-setup` | `OPENSEARCH_URL` set, but step 3 hasn't run yet |
| `restart-needed` | Configured; deploy once more without the recovery admin |
| `reindexing` | Running on OpenSearch; older mail is still being indexed |
| `ok` | Running on OpenSearch |
| `unreachable` | The `opensearch` service is down or not reachable on the private network |
| `auth-failed` | `OPENSEARCH_PASSWORD` differs between the two services |

Mail keeps working whatever the search status is.

## Changing the password

Set a new `OPENSEARCH_PASSWORD` on the `opensearch` service and redeploy it, then
redeploy `iron-id-mail` (it reads the same variable by reference).

## If the index is lost

If the volume is replaced, OpenSearch starts empty. The gateway notices an empty
index and starts a new re-index by itself (at most once per start, 15 minutes after
the previous one). To force it sooner, redeploy `iron-id-mail`.

## After an engine upgrade

The templates repeat the engine's index layout. After upgrading Stalwart, capture the
new layout (the engine creates it in an empty OpenSearch) into a new
`engine-indexes-<version>.json`, point `make-template.js` at it and run
`node make-template.js`.
